# アーキテクチャ原則（Architecture Principles）

* Version: 0.2.0（Proposed / ドラフト）
* Date: 2026-04-01
* Last amended: 2026-09-06
* 上位規範: constitution.md（開発憲章「アーキテクチャの完全性」）

本書は、本プロジェクトのアーキテクチャ原則の正本（SSoT）です。各原則は設計レビューと Class B 判定の根拠になります。

---

## 原則（初期セット・採用組織が拡張）

1. **疎結合・高凝集**: モジュールは単一の責務を持ち、境界を越える結合を最小化する（SHOULD）。
2. **明示的な依存方向**: 依存は一方向とし、循環依存を導入しない（MUST NOT。architecture-standards.md「1.」）。
3. **契約による境界通信**: 境界越えは公開された契約（API・イベント）を通じて行う（SHOULD）。
4. **置換可能性**: 外部依存はアダプタで隔離し、差し替え可能にする（SHOULD）。
5. **可逆性・観測性を既定に**: 本番影響変更はロールバック手段と観測性を備える（SHOULD。憲章）。
6. **分割軸の明示**: モジュール分割は**縦**（機能・ドメイン）を主軸とし、モジュール境界を形づくる。
   **横**（レイヤ。例：プレゼンテーション／アプリケーション／ドメイン／インフラ）は各縦の内部構造であり、
   全機能を貫く一枚板のレイヤを作らない（SHOULD NOT。実体化は [architecture/boundaries.md](boundaries.md)「デプロイ単位」）。
   **物理／論理**（モジュール分割にとどめるか、別デプロイ単位に分けるか）は、縦・横のいずれとも独立した
   第三の軸である。3軸を混同すると、レイヤ単位の分割（横）を機能単位の分割（縦）であるかのように扱ったり、
   論理分割の議論と物理分割の議論を同一視したりする誤りが生じる。
7. **物理分割の遅延**: 既定のデプロイ単位は単一とする（モジュラーモノリス）。物理分割は不可逆であり、
   一度分けたデプロイ単位を実務上統合し直すことはできない（分散モノリス化のリスクを参照。ADR-0009）。
   既定を外し物理分割を選択する場合、「将来〜になりうる」という将来形の理由では足りず、**現在すでに
   成立している**理由（確定済みのベンダ分割契約、セキュリティゾーンの相違、ランタイム特性の相違、
   組織の既存プラットフォーム標準のいずれか）を ADR に記載しなければならない（MUST。判断根拠の正本は
   [ADR-0009](../adr/adr-0009-default-deployment-unit-policy.md)）。
